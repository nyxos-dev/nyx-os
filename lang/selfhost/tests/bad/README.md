# The negative corpus — check.n's anchor

Seventy-eight N programs, each wrong in exactly one way, each rejected by
`ncc` with one located, worded error. `MANIFEST.txt` records the
contract: for every file, the **exact first error line** ncc prints
(`file:line: message`), regenerated by running ncc over the corpus —
never written by hand.

This corpus is the differential anchor for **`check.n`**, the
self-host ladder's third module: where `lex.n` is held to
`ncc --tokens` and `parse.n` to `ncc --ast`, `check.n` must reproduce
these first-error lines — the location *and the wording* — for every
file it claims. A checker that rejects the right programs for the
right reasons, in the reference's own words, is checked in the
strongest sense available.

The corpus doubles as ncc's own regression battery (the verification
suite runs every file and asserts the message), so the two consumers
keep each other honest: a reworded ncc error shows up here as a
manifest diff before it can silently loosen check.n's target.

One normalization: `check.n` accepts a target path through argv and keeps
`/tmp/n_check_target.n` as its no-argument fallback. Both modes preserve
the filename-free diagnostic format: it prints `line: message` and the
differential harness strips the manifest's filename column from the
want side (`cut -d: -f2-`, plus `tr -d '\r'` for autocrlf
checkouts). Location and wording still match to the byte — only the
file's name is normalized away.

The contract has two shapes. Most errors carry a line number, and
the stripped want row reads `line: message`. Declaration errors are
FILE-level — ncc prints them with no line (`file.n: message`) — and
stripping the filename column from one of those leaves the message
with its original **leading space** (` message`). check.n prints
exactly that shape for its FILE-level refusals: a leading space, the
message, no line. One `cut`, two shapes, zero special cases in the
harness.
